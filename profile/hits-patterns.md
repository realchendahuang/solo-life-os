## 双轨内容定位模型（Core Framework）

根据 537 篇推文全量数据与近 7 天爆款表现，账号内容天然呈现**双轨分化**：

```
┌─────────────────────────────────────────────────────────────┐
│ 资产型内容 (Asset Posts)                                     │
│ • 核心特征：藏赞比 (Bookmarks / Likes) ≥ 1.2，甚至藏远大于赞 │
│ • 目标：塑造技术专家权威、沉淀高价值手册、稳定带来精准技术关注│
│ • 典型模式：P1 (情报清单), P2 (架构分层手册), P8 (血泪踩坑复盘)│
└─────────────────────────────────────────────────────────────┘
                               ▲
                               │ 互为飞轮支撑 (探针收割 ➔ 深度交付)
                               ▼
┌─────────────────────────────────────────────────────────────┐
│ 流量型内容 (Flow Posts)                                      │
│ • 核心特征：极简设问/即时热点，超高展开率与回复量，冲破算法池 │
│ • 目标：以问代讲激活评论区、低门槛探针测试社区热度、快速破圈 │
│ • 典型模式：P7 (以问代讲探针), P4 (热点时效吃瓜), P5 (极客暴论)│
└─────────────────────────────────────────────────────────────┘
```

## 选题漏斗：三选三不选

### ✅ 必选（高爆与高留存潜力池）
1. **自己真实验证过的高信噪比信息源与工具箱**：读者最缺乏有效过滤器，藏赞比必定突破 1.2。
2. **高频工程痛点与社区争议的极简问句（P7 探针）**：以问代讲，2~3 句撬动算法推流与评论区案例收割。
3. **一线踩平的坑、版本答案与排除法选型**：算清成本，一锤定音，给出死结论。

### ❌ 坚决不选（低效与扑街池）
1. **纯版本号或功能截图（Changelog / UI 展示）**：读者不是 QA，不关心按钮细节；发产品必须讲开发哲学与痛点。
2. **缺乏立场的二手热点搬运**：没动手跑过、不带算账和锐评的不碰。
3. **空泛的宏大叙事与无具体交付的感叹**：不带具体工具名、不带清单的不碰。
