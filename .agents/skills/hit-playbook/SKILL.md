# Hit Playbook（爆款实战手册）

基于 2026 年 Q3 季度全量 749 万真实曝光、311 篇主推文官方数据提炼的操作型爆款手册。供 `topic-brief`（选题把关）、`post-drafter`（写稿打磨）以及人工写帖时作为最高优先级参考。

---

## 核心工作流

```mermaid
flowchart LR
    A["Raw Idea / 选题"] --> B["四维潜力漏斗 (Filter)"]
    B --> C["匹配爆款蓝图 (Blueprint A-E)"]
    C --> D["套用高爆开篇钩子 (Hook Engineering)"]
    D --> E["草稿生成与排版节奏控制"]
    E --> F["模型内部自检（对照 AGENTS.md §4 宪法）"]
```

> 写稿改稿期间严禁调用任何外部脚本（AGENTS.md §4查/§5）——自检在模型
> 内部逐条对照宪法完成，秒级直出。`audit_post.py` 只保留为按需体检工具：
> 当用户主动说"帮我体检一下这篇稿子"时才运行，绝不作为写作流程的默认闸门。

## 一、选题把关：四维高爆潜力漏斗

在将点子送入 `topic-brief` 或动笔前，用以下四个维度衡量：

1. **痛点微观度（Micro-Pain Point）**：
   - 拒绝宏大叙事（如“AI 将改变编程”）；必须直击具体微观场景（如“没节点就下不了客户端先有鸡先有蛋”、“DeepSeek 没有多模态怎么识图”、“黑框框 TUI 聊天太难受记不住快捷键”）。
2. **现成资产交付感（Deliverable Value）**：
   - 读者能否在 30 秒内跑通或照着做？是否包含 `1. 2. 3. 4.` 极简步骤、配置代码块、脚本或开源仓库？
3. **认知反转（Counter-Intuitive Insight）**：
   - 是否打破了常规共识？（如“大家以为 Pi 是终端替代品，其实核心在 SDK”、“大家以为 OpenCodeGo 是神器，其实已经拉完了”）。
4. **分钱级极端算账（Extreme ROI）**：
   - 能否把成本算到分厘（如“单千张图 0.6 元”、“5美金套餐用到地老天荒”）？越具体的数字越有杀伤力。

## 二、五大黄金结构蓝图（Blueprint A–E）

### 蓝图 A：【隐藏功能挖宝型】（P1 模式，冲曝光与收藏）
* **适用**：官方隐藏功能、免费羊毛、套利技巧。
* **结构**：
  1. **开篇惊叹钩子**：“厚礼蟹！我才知道 [某官方] 居然给每个用户免费提供了 [重磅功能]……”
  2. **痛点代入**：“对于 [具体尴尬场景]，非常有帮助。不用自己对接第三方，官方直接托管了。”
  3. **极简四步上手**：
     - `1. 在地址栏输入...`
     - `2. 进入高级设置...`
     - `3. 搜参数...`
     - `4. 改为 true`
  4. **出处链接**：附带官方文档或一手地址。

### 蓝图 B：【深度横评与版本答案】（P2/P3 模式，建立专家信任）
* **适用**：多工具/框架对比、模型选型、架构方案。
* **结构**：
  1. **钩子**：“最近一直在折腾 [A]、[B]、[C]、[D] 这些 [领域工具]，我终于理解了我自己真正的需求是什么。”
  2. **排除项一（真实痛点）**：“第一：我需要 [需求1]，[A] 实在太难受了，你要记很多……所以我排除了 [A]。”
  3. **排除项二（利益/锁定）**：“第二：我需要 [需求2]，[B] 配置太麻烦，第三方模型总是二等公民，所以我排除了 [B]。”
  4. **一锤定音**：“所以到最后，我真正能选的就是 [C]，如果给它配一个成熟的方案，真正的版本答案是：[项目名]。”
  5. **仓库/配置地址**。

### 蓝图 C：【架构分层手册型】（P2 模式，超高藏赞比 1.5+）
* **适用**：配置仓库、SDK 定制、复杂工作流方案。
* **结构**：
  1. **反差钩子**：“很多人把 [A] 当成 [B] 的替代品，但它真正厉害的不是 [表面UI]，而是 [深层SDK/框架]。”
  2. **由浅到深分四层递进**：
     - `第一层，Prompt 模板：把常用指令写成 Markdown 放在...`
     - `第二层，Skills：按需加载的能力包...`
     - `第三层，Extensions：用 TypeScript 写自定义工具...`
     - `第四层，Packages：打包成 npm 包一键安装...`
  3. **生动比喻收尾**：“所以它不是成品房，是毛坯房加装修工具箱。去照着装就行了。”

### 蓝图 D：【好奇心征集型问句】（P7 模式，算法推流发动机）
* **适用**：开发争议、工作流选型、高频踩坑探讨。
* **结构**（全文极短，2~3 句话）：
  1. **第一句**：“我很好奇一个问题：大家在日常编码工作中会使用 [某个具体技术] 并行开发吗？”
  2. **第二句**：“我感觉大多数人平时 [现存困惑/竞品对比]，平时用不上这个。想知道大家的使用场景是什么？最佳实践是什么？”
  *(评论区自发涌现上百条高质量讨论，算法直接推上热门)*

### 蓝图 E：【痛点对抗与产品打野】（P6 模式，破圈与带粉）
* **适用**：自有产品、开源项目、自动化脚本发布。
* **结构**：
  1. **情绪触发**：“最近被 [某个恶心现象] 给搞烦了。一怒之下写了个工具，叫做 [产品名]。”
  2. **游戏化演示**：“给大家演示一下在评论区打野是多么解压的一件事情。有了它，[痛点解决]。”
  3. **开源共建**：“目前已经把 [屏蔽词/配置/代码] 全部开源公开到官网了。大家看看够全吗？如果有遗漏，欢迎在官网贡献🫡🫡🫡”

## 三、文风自检五问与按需体检

自检默认在模型内部完成（对照上述清单逐条过）。仅当用户明确要求"跑脚本
体检 / 机器审核"时，才运行本 Skill 提供的辅助脚本：

```bash
python3 .agents/skills/hit-playbook/scripts/audit_post.py --file <draft-path>
# 或者直接传入推文文本
python3 .agents/skills/hit-playbook/scripts/audit_post.py --text "厚礼蟹！我才知道..."
# 作为闸门使用：出现 FAIL 时以退出码 2 结束（否则总是 0）
python3 .agents/skills/hit-playbook/scripts/audit_post.py --file <draft-path> --fail-on-fail
```

脚本会顺带列出 `workspace/feedback/ledger.jsonl` 里当前生效的用户反馈约束；
账本某行损坏时会打印警告，而不是静默丢掉你给过的约束。

自检核心指标：
1. **钩子检查**：首行是否在 60 字内换行？是否包含反常识、惊叹词或具体数字？
2. **移动端呼吸感**：单段是否严格控制在 1~2 行？是否有超过 3 行的大文字块？
3. **具体实操感**：是否包含 `1. 2. 3. 4.` 极简步骤或精准分厘算账？
4. **AI 腔剔除**：是否彻底消灭了“在当今”、“总的来说”、“不得不说”、“综上所述”等公关废话？
5. **标志性语言符号**：是否自然带有“穷鬼全家桶”、“版本答案”、“折腾”、“踩坑”、“二等公民”等个人心智印记？
